三方合并：冲突到底是怎么判出来的 ​

先看三个版本：共同祖先 base、当前分支 ours、被合并分支 theirs。逐行比较后，只有「双方都改且改得不一样」的行才会冲突。

自动合并规则：只有一方相对 base 改动时，直接采用该方；双方都改且结果不同，才进入冲突。 这就是 Git 三方合并的全部判断逻辑。

试试只解决一处冲突，观察结果区里的冲突标记如何从两处减少到一处；再点击「重置场景」回到初始状态。

真实仓库里，git merge feature 停下后可以用 git ls-files -u 看到 stage 1/2/3，对应这里的 base / ours / theirs。解决后 git add 会把三个 stage 折叠成 stage 0。
