命令速查表 ​

按使用场景分类，覆盖全站出现的命令。表格中「常用参数」列只列真正会改变行为的那几个，完整参数用 git help <command> 查看。

阅读方式

命令中的 <...> 需要替换，方括号 [...] 表示可选。所有示例在 Git 2.40+ 可用。涉及改写历史或删除数据的命令，统一列在文末「危险命令清单」。

配置 ​

命令说明常用参数
git config --global user.name "<名字>"设置提交作者名--global / --local / --system
git config --global user.email "<邮箱>"设置提交邮箱同上
git config --global core.editor "code --wait"设置提交信息编辑器支持任意编辑器命令
git config --global init.defaultBranch main新仓库默认分支名替代 master
git config --global pull.ff only禁止 pull 产生意外合并only / true / false
git config --global rerere.enabled true记住并复用冲突解法详见协作篇 rerere
git config --global core.autocrlf false关闭个人换行转换，交给 .gitattributesWindows 常用 input
git config --list --show-origin查看全部配置及来源文件--show-scope
git config --get <key>读取单项配置--default
git config --unset <key>删除单项配置--global
git config core.hooksPath .githooks指定钩子目录让钩子脚本随仓库分发
git config alias.<别名> "<命令>"定义命令别名不能覆盖内置命令
git help <command> / git <command> -h查手册 / 快速帮助-w 打开网页版

命令说明常用参数
git merge <branch>合并分支--no-ff 保留合并提交
git merge --squash <branch>压缩为一个待提交变更需手动 commit
git merge --abort放弃本次合并恢复到合并前

git rebase <base>把当前分支变基到 base--rebase-merges 保留合并结构

撤销与恢复 ​

命令说明常用参数
git restore <file>用暂存区内容覆盖工作区--source=<hash> 指定来源
git restore --staged <file>取消暂存，工作区不变--source=HEAD
git restore -p <file>交互式丢弃部分改动危险，逐块确认
git reset --soft HEAD~1撤销提交，改动留在暂存区保留内容首选
git reset HEAD~1撤销提交并取消暂存默认 --mixed
git reset --hard HEAD~1撤销提交并丢弃改动危险，可用 reflog 恢复
git reset --hard <hash>回到指定提交先建备份分支
git revert <hash>反向提交，不改历史已推送场景首选
git clean -n预览将被删除的未跟踪文件先预览再执行
git clean -fd删除未跟踪文件与目录-x 连忽略文件一起删
git reflog查看 HEAD 移动历史-n 20；--date=iso
git reflog show <branch>查看分支指针历史恢复误删分支用
git branch <name> <hash>用历史哈希重建分支救援第一步
git fsck --lost-found --no-reflogs找悬空提交输出在 .git/lost-found/
git cat-file -t <hash>确认对象类型commit / tree / blob

三区撤销速查

想撤销什么命令
工作区改动git restore <file>
暂存区（unstage）git restore --staged <file>
最后一次提交但保留改动git reset --soft HEAD~1
提交并丢弃改动git reset --hard HEAD~1
已推送的提交git revert <hash>

危险命令清单 ​

命令风险替代 / 前置动作
git reset --hard丢弃工作区与暂存区改动先 stash；误操作后查 reflog
git clean -fdx删除所有未跟踪文件，包括 .env先 git clean -n 预览
git branch -D强删未合并分支先 git branch --merged 检查
git push --force覆盖远端历史，可能丢失同事提交改用 --force-with-lease
git rebase 已推送分支他人拉取后历史分叉只 rebase 自己未共享的分支
git commit --amend 已推送提交需要强推才能同步已推送用新提交修正
git filter-repo / filter-branch重写全仓库历史先镜像备份，通知所有协作者
git reflog expire --expire=now --all清空救援记录确认无需恢复再执行
git gc --prune=now立即删除不可达对象救援期间禁用
git update-ref -d <ref>直接删除引用，绕过检查优先用 branch -d
git stash drop / clear删除 stash 记录先 git stash list 确认
git checkout -- <file>丢弃工作区改动且无提示用 git restore 更明确

强推的唯一安全写法

bash
git fetch origin
git push --force-with-lease origin <branch>

--force-with-lease 会在远端分支比你上次 fetch 时更新过的情况下拒绝推送。不要使用 --force，也不要先 fetch 后仍用 --force 掩盖差异。
