24 .gitattributes 与合并策略 ​

.gitignore 决定哪些文件不进仓库，.gitattributes 决定进仓库的文件如何被处理：换行怎么转换、二进制如何 diff、冲突能否自动合并、归档时排除什么。它随仓库提交，对所有人和 CI 生效，是跨平台团队最容易忽略的一份配置。

学习目标 ​

  • 理解跨平台换行、二进制文件和语言统计为什么需要仓库级统一。
  • 掌握 text=auto、eol=lf、binary、-diff 的语义与生效顺序。
  • 能为特定文件配置 diff 驱动与 merge=ours / merge=union / -merge。
  • 能用 export-ignore、linguist-generated 控制归档与统计，并用 git check-attr 排查生效情况。

为什么需要它 ​

问题没有配置的后果对应属性
Windows 提交 CRLFdiff 全文件变更、CI 脚本因 \r 失败text=auto、eol=lf
图片/字体被当文本仓库膨胀、合并产生乱码冲突binary
生成代码计入统计语言占比、覆盖率失真linguist-generated
发布包带测试文档制品体积变大export-ignore

这些规则必须写在仓库里，而不是各人的 core.autocrlf 里：本地配置约束不了同事，也约束不了 CI。

基本语法与生效顺序 ​

每行是 pattern attr1 attr2=value ...，通配符规则与 .gitignore 相同：

text
# 默认自动判断文本/二进制，文本按 LF 存储
* text=auto

# 明确文本文件，检出时统一换行
*.js  text eol=lf
*.sh  text eol=lf
*.bat text eol=crlf

# 二进制：不转换换行，不生成文本 diff
*.png   binary
*.woff2 binary

# 不希望在 diff 中展开
package-lock.json -diff
*.min.js -diff

# 生成代码与第三方代码：折叠 diff、排除统计
dist/**   linguist-generated=true
vendor/** linguist-vendored=true

同一属性被多次匹配时，后写的规则覆盖前面的，所以 * text=auto 放最前，例外放后面。常用属性：

写法含义
text标记文本，提交时统一转 LF
text=autoGit 自行判断，判为文本才规范化
-text强制按二进制处理，禁止换行转换
eol=lf / eol=crlf检出到工作区使用的换行（需配合 text）
binary等价于 -text -diff -merge
-diff不生成文本 diff，显示 Binary files differ
-merge禁止自动合并，冲突时整文件交给人工
merge=union冲突块保留双方内容并拼接

属性只影响之后的文件

修改 .gitattributes 不会重写已入库文件的换行，必须执行 git add --renormalize . 并提交，否则会长期残留 LF/CRLF 混合状态。

换行策略：text=auto 与 eol=lf ​

推荐在 * text=auto 基础上，再给脚本显式加 eol=lf、给 .bat 加 eol=crlf。提交时统一转 LF，检出时按 eol 决定，未指定则遵循 core.eol / core.autocrlf。

建议关闭个人转换，交给仓库属性统一：

bash
git config --global core.autocrlf false
git config --global core.safecrlf warn   # 转换不可逆时警告

检查仓库实际存了什么

bash
git ls-files --eol -- src/ | head
# i/lf w/crlf attr/text=auto  src/win.bat
# i/lf w/lf   attr/text=auto  src/app.ts

i/ 是索引，w/ 是工作区，attr/ 是最终生效属性。排查换行问题比反复 diff 更快。

二进制与 diff 驱动 ​

binary 覆盖大多数场景；需要保留文本 diff 能力时，声明驱动并配置：

bash
# 对应 .gitattributes 中的 *.sql diff=sql
git config diff.sql.textconv cat

对加密文件、压缩包、锁文件使用 -diff，避免 review 时展开无意义内容。

合并策略：ours、union 与 -merge ​

配置分两步：.gitattributes 声明策略名，git config 定义驱动实现。

merge=ours：冲突时保留当前分支 ​

用于自动生成、每个分支各自维护的锁文件或版本文件：

text
package-lock.json merge=ours
version.json      merge=ours
bash
git config merge.ours.driver true    # 必须配置，否则策略不存在

风险：它会静默选择 ours，包括真正需要合并的依赖升级。某分支新增依赖、锁文件却没变，CI 可能因 package-lock.json 与 package.json 不一致而失败。只对「可重新生成且 CI 会校验一致性」的文件使用。

merge=union：保留双方内容 ​

适合追加型文本：变更日志、.gitignore、并列的国际化词条。

text
CHANGELOG.md merge=union
.gitignore   merge=union

风险：union 只保证不出现冲突标记，不保证结果合法。同一位置各加一行依赖可能重复声明；用于代码文件会直接产生语法错误。

-merge：禁止自动合并 ​

text
*.pdf  -merge
*.xlsx -merge

双方都修改时，Git 会明确报冲突（CONFLICT (binary) 或 CONFLICT (content)），保留当前分支版本，由人决定取舍。它不会逐行拼接，因此不会产出半截损坏的文件。

merge=ours 不是万能冲突消除器

它只对声明了该属性的文件生效，且会掩盖依赖/版本变化。不要给源码、数据库迁移脚本配置 merge=ours；迁移冲突必须在合并时人工排序，否则生产环境会漏执行。

归档与语言统计 ​

text
# git archive 生成的发布包中排除开发文件
tests/** export-ignore

# GitHub 语言统计与 diff 折叠
dist/**        linguist-generated=true
third_party/** linguist-vendored=true

export-ignore 只影响 git archive，不影响 clone；linguist-* 只被 GitHub 等平台识别，Git 本身不关心。

排查：属性生效了吗 ​

bash
git check-attr text eol merge diff -- src/app.ts
# src/app.ts: text: auto
# src/app.ts: eol: lf

git check-attr -a -- package-lock.json    # 查看全部属性
git ls-files --eol -- src/app.ts          # 索引与工作区换行

常见「不生效」原因：

现象原因
新克隆换行仍混乱旧文件未执行 add --renormalize
merge=ours 报未知驱动缺少 merge.ours.driver
规则写了却没匹配路径层级或大小写错误，* 不跨 /
例外规则失效后写规则优先，顺序放反
只在本地生效属性文件未提交，只改了 core.autocrlf

一次性重新规范化：

bash
git add --renormalize .
git commit -m "chore: 按 .gitattributes 重新规范化换行"

常见坑 ​

坑后果建议
只配 core.autocrlf每人行为不一致仓库内统一 * text=auto
给源码配 merge=ours静默丢弃对方修改只用于可再生成产物
给代码配 merge=union重复声明、语法错误只用于追加型文本
二进制未标记仓库膨胀、合并损坏binary 或 -merge
改属性后不 renormalize换行问题残留git add --renormalize .
以为 export-ignore 能瘦身 clone只影响 archive瘦身用 LFS 或拆仓库

小结 ​

  • .gitattributes 把文件处理方式变成仓库级契约，优先级高于个人配置。
  • 换行用 * text=auto 打底、脚本用 eol=lf，改完必须重新规范化。
  • binary / -diff 处理二进制与噪音文件；merge=ours 只适合可再生成产物，merge=union 只适合追加型文本，-merge 用于必须人工处理的文件。
  • export-ignore 与 linguist-* 控制归档和统计；排查顺序：git check-attr → git ls-files --eol → 属性文件是否已提交。

规范化流程可以交给钩子自动执行，见 hooks：团队规范自动化；换行报错处理见 报错 FAQ。
