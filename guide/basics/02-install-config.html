02 安装与第一次配置 ​

学习目标 ​

  • 能在 macOS、Windows、Linux 上完成 Git 安装并用 git --version 验证。
  • 能正确设置 user.name 与 user.email，并理解提交作者信息的来源。
  • 能说清 system、global、local 三层配置的位置与优先级。
  • 能配置编辑器、默认分支名与换行符策略。
  • 能完成 SSH 密钥生成、登记与连通性验证，并用 --show-origin 定位配置来源。

安装与版本验证 ​

macOS ​

最轻量的方式是安装 Xcode Command Line Tools，其中自带 Git：

bash
xcode-select --install
git --version
# git version 2.39.5 (Apple Git-154)

Apple 自带版本通常偏旧，需要较新特性时用 brew install git 安装，再用 which -a git 确认路径优先级。

Windows ​

推荐使用 Git for Windows，它提供 Git Bash、凭据管理器和换行符处理：

bash
# Windows PowerShell
winget install --id Git.Git -e --source winget
git --version
# git version 2.47.0.windows.2

Linux ​

bash
# Debian / Ubuntu
sudo apt update && sudo apt install git
# Fedora / RHEL
sudo dnf install git
# Arch
sudo pacman -S git

git --version
# git version 2.43.0

版本低于 2.23 时，git switch、git restore 不可用，建议升级后再跟随本教程。

三层配置与优先级 ​

Git 配置按作用范围分为三层，后读取的覆盖先读取的：

层级参数文件位置典型用途
system--system/etc/gitconfig（Windows 在 Git 安装目录）公司机器统一策略
global--global~/.gitconfig 或 ~/.config/git/config个人身份、编辑器、别名
local--local（默认）<repo>/.git/config单个仓库的远程地址、特殊配置

优先级为 local > global > system。在仓库外执行 git config 且不带层级参数会报错，因为默认写入 local 却没有仓库可写。

设置提交身份：

bash
git config --global user.name "Zhang San"
git config --global user.email "zhangsan@example.com"

user.name 是提交里显示的名字，user.email 用于归属到托管平台账号。邮箱写错时，GitHub/GitLab 无法把提交关联到你，贡献图和权限判断都会出问题。

公司与个人身份分开

在 ~/.gitconfig 中保留个人身份，再用条件包含为工作目录覆盖：

bash
git config --global includeIf."gitdir:~/work/".path ~/.gitconfig-work

~/.gitconfig-work 中写公司的 user.name 与 user.email，进入 ~/work/ 下的仓库会自动生效。用 git config --show-origin user.email 可确认最终命中的是哪个文件。

常用基础配置 ​

编辑器 ​

bash
# VS Code：--wait 让 Git 等待编辑器关闭后再继续
git config --global core.editor "code --wait"
git config --global core.editor
# code --wait

没有配置时，Git 会退回系统默认编辑器（常见是 Vim），不熟悉时容易卡在提交信息界面。

默认分支名 ​

bash
git config --global init.defaultBranch main

新建仓库的初始分支将是 main。已有仓库不受影响，它仍使用创建时的分支名。

换行符 ​

Windows 使用 CRLF，macOS/Linux 使用 LF。跨平台协作时，换行符差异会造成「整文件被修改」的假象。

bash
# Windows：检出时转 CRLF，提交时转 LF
git config --global core.autocrlf true

# macOS / Linux：提交时把 CRLF 转 LF，检出不转换
git config --global core.autocrlf input
平台建议值效果
Windowstrue工作区 CRLF，仓库内 LF
macOS / Linuxinput提交时规范为 LF
全平台统一false + .gitattributes由 text=auto 显式控制

团队项目更可靠的做法是提交 .gitattributes，例如 * text=auto eol=lf，让策略跟随仓库而不是每个人的本机配置。

远程认证：HTTPS 与 SSH ​

HTTPS ​

bash
git clone https://github.com/your-org/your-repo.git

首次推送会要求用户名与密码。GitHub 已不支持账户密码，必须使用个人访问令牌（Personal Access Token，PAT）。macOS 可用钥匙串保存凭据：

bash
git config --global credential.helper osxkeychain   # macOS
git config --global credential.helper manager      # Windows
git config --global credential.helper libsecret    # Linux，需安装 libsecret

SSH ​

bash
ssh-keygen -t ed25519 -C "zhangsan@example.com"
# Enter file in which to save the key (/Users/zhangsan/.ssh/id_ed25519): 直接回车
# Enter passphrase: 可留空或设置口令

启动 agent 并加入私钥，然后把公钥内容粘贴到 GitHub/GitLab 的 SSH Keys 设置中：

bash
eval "$(ssh-agent -s)"
ssh-add ~/.ssh/id_ed25519

cat ~/.ssh/id_ed25519.pub
# ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAA... zhangsan@example.com

验证连通性：

bash
ssh -T git@github.com
# Hi zhangsan! You've successfully authenticated, but GitHub does not provide shell access.

出现 Hi <username>! 即成功；Permission denied (publickey) 通常表示公钥未登记、私钥未加入 agent，或连接到了错误的账号。

排查配置来源 ​

配置被覆盖时，先看最终生效值和它来自哪个文件：

bash
git config --list --show-origin
# file:/Users/zhangsan/.gitconfig    user.name=Zhang San
# file:/Users/zhangsan/.gitconfig    user.email=zhangsan@example.com
# file:.git/config    remote.origin.url=git@github.com:your-org/your-repo.git

只看某一项：git config --show-origin user.email。清理错误配置用 git config --global --unset user.email，或 git config --global --edit 直接编辑文件。

不要把私钥交给任何脚本

id_ed25519 是私钥，只能留在本机 ~/.ssh 且权限为 600。需要给 CI 使用时，应使用部署密钥（Deploy Key）或短期令牌，而不是复制个人私钥。

常见坑 ​

提交邮箱与账号邮箱不一致

提交能成功，但托管平台显示为「未关联作者」，也不会计入贡献。修复历史需要改写提交（git commit --amend 或交互式变基），已推送的公共分支不应随意改写。

git config --list 有重复项是正常的

同一个键可能在 system、global、local 各出现一次，后面的覆盖前面的。用 --show-origin 看清层级，不要看到两行 user.name 就以为配置冲突。

小结 ​

  • 安装后用 git --version 验证，低于 2.23 无法使用 switch / restore。
  • 提交身份由 user.name 与 user.email 决定，必须与托管平台账号匹配。
  • 配置分 system、global、local 三层，优先级依次升高。
  • core.editor、init.defaultBranch、core.autocrlf 是最值得先设置的三个选项。
  • HTTPS 依赖令牌，SSH 依赖密钥；用 --show-origin 能快速定位配置来源。
