05 分支入门：HEAD 与引用 ​

学习目标 ​

  • 能说明分支本质上是指向提交的可移动指针，并定位 .git/refs/heads 中的对应文件。
  • 能解释 HEAD 的作用，以及什么情况下会进入游离头指针（detached HEAD）。
  • 能使用 git branch、git switch、git switch -c 完成分支的创建、切换与删除。
  • 能写出旧命令 git checkout 与新命令的对应关系。
  • 能用 ASCII 图推演新建分支、切换分支、提交后指针的移动方向。

分支只是一个指针 ​

Git 的提交通过父指针串成有向图。分支（branch）不是提交的副本，也不是目录的拷贝，而是一个指向某个提交的引用（ref），文件位于 .git/refs/heads/<branch>，内容就是提交哈希。

text
main
 |
 v
* 3f2a1c9 feat: 登录接口
* 8b1e0d4 fix: 修复超时
* 2a9c7f1 chore: 初始化项目
bash
cat .git/refs/heads/main
# 3f2a1c9a1b2c3d4e5f60718293a4b5c6d7e8f901

git rev-parse main
# 3f2a1c9a1b2c3d4e5f60718293a4b5c6d7e8f901

git branch -v
# * main 3f2a1c9 feat: 登录接口

创建分支只是写入一个包含哈希的小文件，因此几乎零成本。这也是 Git 鼓励「一个任务一个分支」的根本原因。

HEAD：当前所在的引用 ​

HEAD 是一个符号引用（symbolic ref），通常指向当前分支，而不是直接指向提交：

bash
git symbolic-ref HEAD
# refs/heads/main

当你在 main 上提交时，HEAD 不动，main 指针向前移动到新提交。切换分支时，HEAD 改为指向另一个分支，工作区随之更新。

text
提交前：
HEAD -> main -> 8b1e0d4

提交后：
HEAD -> main -> 3f2a1c9 -> 8b1e0d4

游离头指针（detached HEAD） ​

当 HEAD 直接指向某个提交哈希，而不是分支时，就处于 detached HEAD 状态。常见触发方式：

bash
git switch --detach 8b1e0d4
# HEAD is now at 8b1e0d4 fix: 修复超时

也可以检出标签或远程分支的某个提交，效果相同。此时：

text
HEAD -> 8b1e0d4
main -> 3f2a1c9

工作区显示的是 8b1e0d4 的内容，可以查看、编译、实验，但在此状态下创建的新提交不属于任何分支。一旦切走，这些提交只能通过 reflog 找回。

不要在游离 HEAD 上直接开发

提交后切回 main，会看到 Warning: You are leaving 1 commit behind。正确做法是立即基于当前位置建分支：

bash
git switch -c rescue/experiment

这样 HEAD 重新指向分支，已有提交也被纳入引用，不会丢失。

创建、切换与删除分支 ​

bash
git branch                      # 列出本地分支，* 表示当前分支
# * main
#   feature/login

git branch -vv                  # 附带上游分支与最后一次提交
# * main          3f2a1c9 [origin/main] feat: 登录接口
#   feature/login 4c5d6e7 feat: 登录页面

git branch feature/login        # 在当前提交上创建分支，但不切换
git switch feature/login        # 切换过去
# Switched to branch 'feature/login'

git switch -c feature/payment   # 创建并切换
# Switched to a new branch 'feature/payment'

删除与重命名：

bash
git branch -d feature/login
# Deleted branch feature/login (was 4c5d6e7).

git branch -D feature/experiment   # 强制删除未合并分支

-d 会检查分支是否已合并，未合并时拒绝删除，这是防止误删提交的保护。-D 跳过检查，只应在确认提交已无用或已另行保存时使用。

新旧命令对照 ​

git switch 与 git restore 从 Git 2.23 起用于拆分 git checkout 的职责：前者管分支，后者管文件。旧命令仍然可用，但语义容易混淆。

旧命令新命令作用
git checkout maingit switch main切换分支
git checkout -b feature/xgit switch -c feature/x创建并切换
git checkout <commit>git switch --detach <commit>进入游离 HEAD
git checkout -- <file>git restore <file>丢弃工作区修改
git checkout <commit> -- <file>git restore --source=<commit> <file>取回历史版本文件

在脚本或旧文档里看到 checkout，先判断它操作的是分支还是文件，再决定替换为哪条新命令。

指针移动的完整推演 ​

从一个提交开始：

text
main
 |
 v
* 2a9c7f1 chore: 初始化项目

执行 git switch -c feature/login：

text
main            feature/login
 |                    |
 v                    v
* 2a9c7f1 chore: 初始化项目

两个分支指向同一个提交。随后在 feature/login 上提交两次：

text
                        HEAD -> feature/login
                               |
                               v
* 8b1e0d4 feat: 登录页面     ← feature/login
* 3f2a1c9 feat: 登录接口
* 2a9c7f1 chore: 初始化项目   ← main

执行 git switch main：

text
* 8b1e0d4 feat: 登录页面     ← feature/login
* 3f2a1c9 feat: 登录接口
* 2a9c7f1 chore: 初始化项目   ← HEAD -> main

工作区回到 main 指向的 2a9c7f1，feature/login 的提交仍然存在于对象库中。再执行 git merge feature/login，main 指针会向前移动，这就是下一篇要讲的快进合并。

分支命名与清理 ​

企业项目通常用「类型/范围」命名，避免 dev2、zhangsan-test 这类无法判断用途的名字：

前缀用途示例
feature/新功能feature/login-sms
fix/缺陷修复fix/order-amount-zero
hotfix/线上紧急修复hotfix/payment-timeout
release/发布准备release/1.4.0
chore/构建、依赖、配置chore/upgrade-vite

查看分支合并情况，辅助清理：

bash
git branch --merged main      # 已合入 main，可以安全删除
git branch --no-merged main   # 尚未合入，删除前需确认

常见坑 ​

游离 HEAD 上的提交会「消失」

在 detached HEAD 状态提交后直接切换分支，提交不在任何分支上，git log 看不到。用 git reflog 找到哈希后 git switch -c rescue <hash> 可恢复。不要依赖「我记得提交过」。

-D 会直接丢弃未合并的提交

git branch -d 拒绝删除是有原因的。被删除分支的提交暂时还能通过 reflog 找回，但 reflog 会过期（默认 90 天），并不是长期保险。删除前先确认 git branch --no-merged 的输出。

分支名不能与已有目录冲突

Git 把引用存成文件路径，feature 与 feature/login 不能同时存在，因为前者需要是文件、后者需要是目录。命名时直接用 feature/login，不要先建一个叫 feature 的分支。

小结 ​

  • 分支是指向提交的可移动指针，存放在 .git/refs/heads，创建成本极低。
  • HEAD 通常指向当前分支；直接指向提交时进入 detached HEAD。
  • git switch 管分支，git restore 管文件，二者替代了 git checkout 的混合语义。
  • 在分支上提交只移动该分支指针，其他分支保持不动。
  • 删除分支前用 --merged / --no-merged 判断是否安全。

分支之间如何汇合，见 06 分支合并与快进。
